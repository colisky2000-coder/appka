# appka

## Архитектура
- `cabinet/` — основной проект: личный кабинет + обучающая платформа. Flask + SQLAlchemy (SQLite локально, Postgres на хостинге), фронтенд — SPA на обычном JS в `cabinet/static/` (`core.js` — оболочка и роутер, `user.js` — страницы пользователя, `admin.js` — админка), сборки нет.
- Корень репозитория (`server.py`, `app.jsx`, `frontend/`) — отдельное старое приложение Telegram Web App, с кабинетом не связано.

## Запуск и проверка (cabinet)
```bash
cd cabinet
pip install -r requirements-dev.txt
ADMIN_EMAIL=admin@example.com ADMIN_PASSWORD=admin12345 SEED_DEMO=1 python wsgi.py   # http://localhost:8000
python -m pytest -q                                                                 # тесты (SQLite в памяти)
TEST_DATABASE_URL=postgresql://... python -m pytest -q                              # тесты на Postgres
```
- Windows: двойной клик `cabinet/start.bat` (вход `admin@site.ru` / `admin12345`).
- Переменные окружения — в `cabinet/.env.example`.

## Всегда
- Перед задачей читать `memory/gotchas.md` и `memory/decisions.md`.
- Деньги хранить в копейках (int), наружу отдавать через `rub()` / принимать через `to_kop()`.
- Новые колонки — только добавлением в `backend/models.py`: их создаёт `auto_migrate` при старте.
- Изменяющие запросы к `/api/` фронтенд шлёт с заголовком `X-Requested-With: fetch` (иначе 400).
- Перед коммитом: `python -m pytest -q` в `cabinet/` зелёный.
- Тексты интерфейса — на русском.

## Никогда
- Не коммитить `.env`, токены, `cabinet/instance/` и файлы `*.db`: там живые данные пользователя.
- Не просить секреты (токен бота и т. п.) в чат — только через `.env` или переменные хостинга.
- Не переименовывать и не удалять колонки в расчёте на `auto_migrate`: он умеет только добавлять.
- Не возвращать продажу строк с контактами («Закуп трафика») и публичные формы, где клиент вводит ИНН/ФИО (удалены 2026-09-25, см. decisions.md).

## Память проекта (`memory/`)
- `gotchas.md` — грабли и неочевидные подвохи.
- `bugs.md` — баги и их статус.
- `decisions.md` — принятые решения и почему.
- `todo.md` — что дальше.

Правила записи:
- Писать сразу, как только: что-то сломалось и пользователь это починил; пользователь поправил; выбрали один вариант из нескольких; нашёлся неочевидный подвох.
- Одна строка на запись, с датой: `- 2026-09-25 — текст`.
- Сначала искать похожую запись: дубликаты не плодить, старую обновлять (дату — на дату обновления).
- На «запиши в память» — самому решить, что из сессии важно, и разложить по файлам.
