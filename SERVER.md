# Сервер (VPS) — деплой и управление через GitHub Actions

Напрямую по SSH облачный Claude подключиться не может (из его среды открыт только HTTPS),
поэтому на сервер ходит GitHub Actions: он подключается по SSH и выполняет команды.

```
Claude меняет код → пуш в GitHub → GitHub Actions → SSH → сервер
```

## Что где лежит

| Файл | Что делает |
|------|------------|
| `.github/workflows/deploy.yml` | Пуш в `main` → собрать фронтенд, выложить релиз на сервер, перезапустить, проверить, при ошибке откатить |
| `.github/workflows/server-run.yml` | Пуш изменений `ops/run.sh` в ветку `claude/**` → выполнить этот скрипт на сервере (обслуживание, диагностика) |
| `ops/run.sh` | Скрипт для разовых команд на сервере; вывод — в логах Actions |
| `deploy/remote-deploy.sh` | Выполняется на сервере при деплое |
| `deploy/appka.service` | systemd-сервис приложения (gunicorn на `127.0.0.1:5000`) |

На сервере: код в `/opt/appka/current` (ссылка на `/opt/appka/releases/<коммит>`, хранятся 5 последних),
Python-окружение в `/opt/appka/venv`, переменные приложения в `/etc/appka/appka.env`, сервис `appka`.

## Настройка (один раз)

GitHub → репозиторий → **Settings → Secrets and variables → Actions → New repository secret**:

| Секрет | Значение |
|--------|----------|
| `SERVER_HOST` | IP сервера |
| `SERVER_USER` | `root` (можно не задавать — по умолчанию root) |
| `SERVER_PASSWORD` | пароль SSH (или вместо него `SERVER_SSH_KEY` — приватный SSH-ключ) |
| `BOT_TOKEN` | токен бота от BotFather |
| `SPREADSHEET_ID` | ID Google-таблицы |
| `GOOGLE_CREDENTIALS_BASE64` | ключ сервисного аккаунта Google в Base64 (`python to_base64.py`) |

Секреты приложения при каждом деплое записываются в `/etc/appka/appka.env`; незаданные не трогаются.
Туда же вручную можно добавить `PORT=...` / `HOST=...`, чтобы сменить адрес gunicorn.

## Как обновлять сайт

1. Попроси Claude изменить функционал — он сделает изменения в ветке.
2. Изменения попадают в `main` (merge PR) → автоматически запускается «Деплой на сервер».
3. Результат — во вкладке **Actions**. Если новая версия не поднялась, остаётся работать предыдущая.

Задеплоить заново без изменений: **Actions → Деплой на сервер → Run workflow**.
