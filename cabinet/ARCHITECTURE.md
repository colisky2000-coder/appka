# Кабинет: как устроен проект

Документ для разработчика или ИИ-ассистента, который впервые открывает проект. Правила работы и память проекта — в `../CLAUDE.md` и `../memory/`.

## Что это
Личный кабинет с обучающей платформой. Пользователь проходит программу обучения (роадмап → уроки → материалы), видит новости, пишет в поддержку. Доступ к разделам определяется тарифом. Регистрация — только по ссылке-приглашению от админа, с подтверждением через Telegram-бота. Админка управляет всем содержимым.

## Стек
- **Бэкенд:** Python 3.9+, Flask, SQLAlchemy 2. База: SQLite (`instance/cabinet.db`) локально, Postgres через `DATABASE_URL`.
- **Фронтенд:** SPA на обычном JS без сборки (`static/`). Роутинг по `location.hash` (`#/learn`, `#/a-invites`…).
- **Шрифты:** Benzin Semibold (крупный текст), Yandex Sans Text (основной) — `static/fonts/`. Акцентный цвет — красный.
- **Зависимостей минимум:** `requirements.txt` (flask, sqlalchemy, psycopg, gunicorn). Для тестов — `requirements-dev.txt` (+pytest).

## Запуск
- Windows: `start.bat` → http://localhost:8000.
- Вручную: `pip install -r requirements-dev.txt && python wsgi.py`.
- Тесты: `python -m pytest -q`.
- Настройки — файл `.env` рядом с `wsgi.py` (образец `.env.example`). Главное:
  - `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` — без них регистрация по приглашениям не работает;
  - `PUBLIC_URL` — внешний адрес. Если он начинается с `https://`, бот работает через вебхук, иначе кабинет сам опрашивает Telegram (getUpdates) — так работает локально;
  - `URL_PREFIX` — если кабинет живёт в подпапке сайта (например `/secret`);
  - `DATABASE_URL`, `ADMIN_*` (первый админ), `SEED_DEMO=1` (демо-данные на пустой базе).

## Данные (backend/models.py)
- **Доступ:** `Tariff` (цена, срок, набор разделов `features`, привязанная программа), `User` (логин, пароль, Telegram id/chat_id, тариф, баланс, роль user/admin), `UserSession`, `Invite` (ссылка `/join/<код>` на тариф: лимит регистраций `max_uses`, срок доступа `days`, срок действия ссылки `expires_at`), `TgSignup` (временная запись регистрации с кодом из бота).
- **Обучение:** `Program` → `Step` (точки роадмапа, ведут на урок/статью/ссылку) → `StepTask` (галочки); `Lesson` (видео по ссылке + HTML-описание); отметки прогресса `TaskDone`, `StepDone`, `LessonDone`; привязка материалов к программам `ArticleProgram`, `MaterialProgram`.
- **Контент:** `Article` (статьи, HTML), `Material` (файлы в БД), `Upload` (картинки из редактора), `News` + `NewsRead`, `TeamMember`, `Setting`.
- **Поддержка и баланс:** `Ticket` + `TicketMessage`, `BalanceTx`, `TopUpRequest` (заявка на пополнение, одобряет админ).
- **Партнёрка (раздел пока из шаблона):** `Offer`, `OfferLink`, `Click`, `Favorite`, `Conversion`.
- У `Article`, `Material`, `Lesson`, `Program` есть обложка (`CoverMixin`), отдаётся по `/media/<тип>/<id>/cover`.
- Деньги везде в копейках (int).

## Ключевые сценарии
**Регистрация (только по приглашению):**
1. Админ: «Админка → Приглашения» → создаёт ссылку на тариф (можно несколько на тариф, с лимитом).
2. Человек открывает `/join/<код>` → «Получить код» → `POST /api/auth/tg/start` возвращает ссылку `t.me/<бот>?start=<токен>`.
3. Бот получает `/start <токен>` и присылает 6-значный код (действует 15 минут, число попыток ограничено).
4. Человек вводит код → `POST /api/auth/tg/check` → придумывает логин и пароль → `POST /api/auth/register`: создаётся пользователь с тарифом из приглашения, счётчик использований ссылки растёт.
5. Дальше вход — логином и паролем (`POST /api/auth/login`). Один Telegram = один аккаунт.

**Тарифы и разделы:** у тарифа галочки из `features.FEATURES` (dashboard, learning, manuals, offers, favorites, conversions, stats, income, support, billing). Бэкенд проверяет доступ через `features.require(...)`, фронтенд строит меню через `App.can(...)`. Админ видит всё и может «смотреть сайт глазами тарифа».

**Обучение:** страница «Роадмап» (`#/learn`) — шаги с задачами и прогрессом; «Уроки» (`#/lessons`, `#/lesson/<id>`) — видео (YouTube, RuTube, VK Видео, Vimeo, Дзен) и описание; «Материалы» (`#/learn-materials`) — статьи и файлы программы карточками с превью.

**Редактор:** `editor.js` отдаёт HTML, сервер чистит его в `richtext.py` (белый список тегов, только разрешённые плееры в iframe). Картинки загружаются через `POST /api/admin/uploads` и хранятся в БД (`/media/u/<ключ>`). Старые тексты в простом формате («# заголовок», «- пункт») продолжают отображаться.

## Соглашения
- Все изменяющие запросы к `/api/` — с заголовком `X-Requested-With: fetch`, иначе 400 (защита от CSRF). В `core.js` это делает `App.api`.
- Ответы API: `{"ok": true, "data": ...}` или `{"ok": false, "error": "текст для пользователя"}`.
- Схема БД меняется только добавлением колонок в models.py — `auto_migrate` добавит их при старте. Переименование/удаление колонок он не делает. Удалённые таблицы перечисляются в `db.OBSOLETE_TABLES` и стираются при старте.
- Пути во фронтенде относительные (`api/...`, `static/...`), чтобы кабинет работал в подпапке.
- Тексты интерфейса на русском; редактируемые тексты страниц — в `settings.SCHEMA`.
- Секреты только в `.env`; `.env`, `instance/`, `*.db` не коммитятся.
- Удалены намеренно и не возвращаются: продажа строк с контактами («Закуп трафика») и публичные формы, где клиент вводит ИНН/ФИО.
